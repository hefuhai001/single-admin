# 安全策略

## 支持的版本

single-admin 目前处于快速迭代阶段，仅对最新 `master` 分支及最近一次发布版本提供安全修复。

| 版本 | 是否支持 |
| --- | --- |
| `master`（最新代码） | 是 |
| 最近一次 Release | 是 |
| 更早的历史版本 | 否 |

## 报告漏洞

**请不要通过公开 Issue 报告安全漏洞。**

请使用 GitHub 的私密漏洞报告功能：

1. 打开仓库的 **Security** 标签页；
2. 点击 **Report a vulnerability**；
3. 填写漏洞详情并提交。

如果无法使用该功能，请通过仓库主页公开的联系方式与维护者取得联系，并在标题中注明 `[SECURITY]`。

## 报告内容

为便于快速定位，请尽量提供：

- 受影响的版本或 commit；
- 漏洞类型（如认证绕过、越权、SQL 注入、任意文件上传、XSS、敏感信息泄露等）；
- 复现步骤或最小复现环境；
- 影响范围与可能的利用方式；
- 已知的缓解措施（如有）；
- 你希望公开披露的时间（如有）。

请**不要**在报告中附带真实生产环境的数据库密码、Token、对象存储密钥等敏感信息，必要时请脱敏。

## 处理流程

| 阶段 | 说明 |
| --- | --- |
| 确认 | 收到报告后尽快确认并回复 |
| 评估 | 判断影响范围与严重等级，必要时与你沟通细节 |
| 修复 | 在私有分支完成修复并补充测试 |
| 披露 | 修复版本发布后，在 Release Notes 中说明问题与修复方式 |

在修复发布前，请勿公开漏洞细节。修复发布后，欢迎你以贡献者身份补充安全公告。

## 安全基线

部署到生产环境前，请至少完成以下检查：

- 修改数据库默认账号，应用使用最小权限账号连接；
- 配置强密码的 Redis，且不要将 MySQL / Redis / MinIO 端口直接暴露到公网；
- 启用 HTTPS，并为 Nginx 配置安全响应头（CSP、`X-Content-Type-Options`、`X-Frame-Options` 等）；
- 首次登录后立即修改初始管理员密码；
- 关闭生产环境的接口文档（`application-prod.yaml` 已默认关闭）；
- 在系统配置中填写真实的 OSS / 邮件凭据，不要将凭据提交到仓库；
- 定期执行依赖与镜像漏洞扫描。

更完整的改进项与优先级见 [IMPROVEMENTS.md](IMPROVEMENTS.md)。
